## Rendering model

The board renders a `2 * visibleDist` square window centered on the player (`visibleDist` 9, so 18×18 cells), not the whole 32×32 map. Cells outside `clearDist` (7) render at 0.75 opacity, outside `visibleDist` at 0. That opacity gradient is the fog of war — there is no separate visibility computation.

Re-rendering the whole window every keypress is fine. It is turn-based, ~324 cells, and the original does exactly this. Do not add virtualization.

`entitiesByPos` (phase 3) builds a `PosKey → Layer → Entity[]` index, memoized per `entities` object identity in a `WeakMap` — one build per state change, however many renders read it. Cells call `entitiesAt`, which flattens a cell in layer order `floor, between, occupy, above` with dead entities sorted below living ones in each layer, so corpses appear under items. Don't re-derive any of that ordering in JSX — it's already done.

## Keyboard input

The original attaches listeners via a Reagent ref callback and stashes the handler on `window._game-key-handler` to remove it later. In React, this is a `useEffect` with a cleanup return — the stashing hack is unnecessary.

Key codes from `key-dir-map`: arrows (37/39/38/40) and vim keys (h/l/k/j = 72/76/75/74), plus `.` (190) to rest. Also `?` (191) toggles help and `Esc` (27) closes it. The handler maps keys to `Dir` (from `engine/movement.ts`, phase 5) and calls `takeTurn(state, dir, rng)` — the combat `Rng` is created once per level from ambient entropy (`makeRng(randomSeed)`; entropy is injected at the edge, per PLAN.md) and held in the UI layer (a ref, not state); see phase 5's "The RNG is injected".

The help-open flag is UI-local `useState` in App, not `GameState` — the original kept `:modal` in its one big persisted atom (`ui.cljs:326-327`), but a help overlay has no business surviving a reload. There is no message line or pickup modal to port: both are dead code in the original and their fields were dropped from the types (see phase 5's omissions).

`keyCode` is deprecated but works everywhere and the original uses it. Port to `event.key` instead — it is clearer (`'ArrowLeft'`, `'h'`, `'.'`) and the on-screen arrow buttons stop needing synthetic `KeyboardEvent`s with fake keycodes, which is the ugliest part of the original UI (`trigger-key`). Have the buttons call the same `takeTurn` action the keyboard handler calls.

## Animations

Entities carry `animation: Animation` — an object `{ name, disposal?, frame? }` (`types.ts`), not the original's `[name, disposal, frame]` tuple. Two mechanisms:

- **Bump.** `move-to` sets `bump-left|right|up|down` when a move is blocked. Pure CSS, keyed off a class.
- **Destroy-on-end.** Smoke puffs and collision markers carry `disposal: 'destroy'`; the `onAnimationEnd` handler removes the entity from state. Port this — it is how transient effects get cleaned up.

`replay-pop-animation-on-change` in `emoji.cljs` is a DOM hack to restart a CSS animation by removing the class, forcing reflow via `offsetHeight`, then re-adding it. It relies on the sprite being an `<img>` with an `onload`. Since sprites are now URL-referenced files that may be cached (no reliable `onload`), re-implement this as a React `key` change instead — changing the key remounts the element and restarts the animation, which is the idiomatic equivalent and less fragile. `Animation.frame` exists for exactly this: include it in the key. The original sets it to the move counter on each bump (`engine.cljs:83`), which is what makes a repeated bump replay.

## Health bars

One trap inherited from the id migration: the original memoizes `component-health-bar` on entity *copies* (`ui.cljs:91`), which self-refreshed because combat re-copied combatants each round. `state.combatants` now holds stable ids while HP changes underneath, so a `React.memo` keyed on the id renders stale bars forever. Memoize on `(id, hp)` or not at all — 324 turn-based cells don't need it. And per phase 5: skip combatant ids that no longer resolve in `state.entities`.

## CSS

`style.css` is mostly self-contained and ports as-is. Strip: the landing-page styles (`body.page`), the ad block, and the `#loading` spinner. Keep the grid, tile, animation, health bar, and modal rules.

## Tombstone / share string

`make-share-string` builds the emoji summary two ways from one function — passing either `emoj` (text characters, for clipboard) or `tile-mem` (image elements, for display), with `"\n"` or `<br/>` as the separator. That is a nice bit of factoring; keep the shape, typed as a generic over the render target.

The original's version reads `:statistics` out of game state (`ui.cljs:193`, `210`); statistics are run-scoped now, so the ported function takes `(state, statistics)`. Until phase 7 introduces the persistent run layer, App holds a transient in-memory `Statistics` (via `emptyStatistics()`, reset on reload) — fine for the phase-6 milestone; phase 7 makes it durable.

Drop from the tombstone: the social-media search links (Mastodon/Bluesky/Threads/X), the `component-game-ad` block, and the feedback mailto. Keep the stats block and the share button — though note that phase 7 replaces the "next rogule" countdown with the pomodoro timer, and phase 8 makes the whole tombstone appear only on death rather than on every level completion.
